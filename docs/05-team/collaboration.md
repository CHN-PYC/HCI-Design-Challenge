# 合作开发方式

## 已记录的协作规则

1. **先统一，再分工**：页面风格和框架由团队统一确定后，才开始多人分工设计。
2. **AI 输出必须人工核对**：尤其竞品不足、来源和用户反馈，不能直接作为事实。
3. **首轮聚焦基础功能**：首轮不追求完整功能集，后续根据第二轮调研迭代。
4. **原型边界明确**：Figma 需要可点击交互，但无需实现真实拍照、数据导入等底层功能。
5. **外部依赖提前说明**：进入原型前需要说明所需 API 与现实可行性。

## 尚未确定

源文档指定第三次会议讨论“确定小组合作开发方式”，但尚未记录结论。以下项目不能视为已决定：

- 主分支/功能分支策略
- 代码评审方式
- 设计文件版本与命名规范
- 任务分配与周节奏
- 是否使用同一套设备/模拟器测试
- 文档、设计稿和代码之间的责任人
- 问卷和用户数据的访问权限

## 建议的最低协作基线

> 以下是本仓库初始化时建议采用的默认做法，待小组确认后可转为正式约定。

- 每个任务在任务看板有 ID、负责人、状态和来源。
- 研究结论链接到问卷/竞品来源；设计决策链接到研究发现。
- 原始记录不覆盖；更新时新增日期化版本。
- 合并前至少一名成员检查；涉及研究伦理时增加负责人审核。
- 任何功能取舍都记录“为什么不做”，防止范围重新膨胀。
