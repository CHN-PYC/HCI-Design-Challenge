# 初步技术可行性

> 这些是源文档中的可行性候选能力，不代表已经确定的 MVP 范围。

| 能力 | 潜在用途 | 可行性/限制 | 状态 |
| --- | --- | --- | --- |
| GPS | 识别大致位置和附近地点，支持基于位置的健康建议 | 智能手机支持；后台位置访问受限，需要合适权限 | 待调研 |
| Weather API | 根据天气和预报支持户外活动建议 | 可通过 Open-Meteo 等服务实现；是否使用取决于用户研究发现 | 可选 |
| Notifications | 无需用户打开 App 即可主动提供健康建议 | 移动操作系统支持；受通知权限和后台执行限制 | 待调研 |
| User Preferences | 收集健康目标、饮食偏好和提醒设置，用于个性化 | 用户输入与 App 设置即可实现；不是外部数据源 | 待调研 |
| Recipe API | 获取食谱，并结合菜系、预算和用餐时间推荐 | 可使用 TheMealDB 等 API；具体字段、授权和使用限制待核实 | 待调研 |

## 需要进一步验证的问题

- 为实现原型要展示的交互，哪些 API 必须存在、哪些只需在界面中模拟？
- GPS、天气或食谱数据是否真的能改善用户价值，而不是增加复杂度？
- 通知触发需要哪些权限和后台能力？
- 健康、位置、饮食和偏好数据如何最小化收集、保存和展示？
- 第三方 API 的可用性、费用、速率限制和隐私条款是否满足课程原型需要？

## 原型边界

第二次会议明确：Figma 原型需要可点击并能说明现实可行的外部 API 依赖，但不要求真正实现数据导入、拍照识别等底层功能。
