# Figma 原型规范

## 目标

用可点击的手机端原型验证核心任务流、主动建议方式与用户控制；原型应足够真实地展示外部数据在界面中的作用，但不要求实现底层能力。

## 当前交付要求

### 必须包含

- 统一视觉语言与组件规范。
- 核心任务的可点击页面流，按钮连接真实目标页面。
- 与首轮基础功能对应的页面，不加入尚未验证的附加功能。
- 对外部 API 依赖的清晰标注（例如位置、天气、食谱）。
- 主动建议状态，以及接受、推迟、拒绝/关闭等控制方式（如果研究确认该方向）。
- 通知、权限或隐私设置的必要入口（范围待用户研究确认）。

### 不要求

- 真实调用 GPS、天气或食谱 API。
- 真正导入数据或进行拍照识别。
- 完整后端、账户系统或商店发布。

## 页面规划

> 页面清单尚未确定。不要提前固定首页模块；第二次会议已指出首页重点需由用户功能偏好调研决定。

| 体力活动 | 候选方向，取决于研究结果 | 待调研 |
| 作息 | 候选方向，取决于研究结果 | 待调研 |
| 识别/输入 | 拍照或数据输入仅作界面示意 | 待调研 |
| 通知与隐私设置 | 控制建议和数据权限 | 待设计 |

## 交付前检查

- [ ] 已从统一方案开发，视觉结构和交互方式一致。
- [ ] 每个关键按钮都连接到明确页面，不是死链或占位点击。
- [ ] 原型中能说明哪些数据是真实需求、哪些仅为模拟。
- [ ] 没有把待确认功能当作已确定 MVP。
- [ ] 已完成一次团队内部点击走查。
- [ ] 已完成至少一名目标用户的原型测试并记录问题。
